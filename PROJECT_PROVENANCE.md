# Butler AI Project Provenance Rule

## Product Authorship

Butler AI is developed as an **original, proprietary, privacy-first** self-hosted PC automation product. New implementation code must be authored for Butler’s own data models, visual system, authorization boundary, and paired-PC protocol. External projects, articles, and documentation may inform high-level patterns or platform constraints, but their source code, copy, and visual assets must not be copied into the product.

## Supplied Materials

Files supplied by the project owner are treated as project reference material. They are not merged blindly: each item must be inspected for interface compatibility, security impact, active dependencies, and provenance signals before it is retained, adapted, or replaced. When a safe idea from supplied material is incorporated, its resulting Butler implementation should be adapted to the current project’s conventions and recorded in the relevant audit or design document.

## Efficiency Rule

Work should favor targeted checks and well-supported improvements over repeated broad scans, speculative rewrites, or duplicate systems. Existing validated Butler functionality remains in place unless evidence demonstrates a safety, privacy, performance, or compatibility gap.
